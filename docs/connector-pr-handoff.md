# EP News connector PR handoff

Editorial authority: [current Master Workflow PDF](https://drive.google.com/file/d/1-S44eeR25lVsO9WVCEdz2SPgAAAcTtpm/view). Retrieve on every run; use current main for technical schemas and validators. Website-only is default; social approval is separate.

After intake finalization, the orchestrator must verify the remote candidate SHA, finalization commit, and successful intake validation before opening a PR through the authenticated GitHub connector (not GITHUB_TOKEN). Check existing PRs for the exact branch first. Open one non-draft PR, verify head SHA, wait for all required independent checks and preview review, then request publisher merge approval. Never bypass failed or action-required checks. No additional credentials are stored in GitHub. If connector-created PRs still require authorization, stop and inspect repository policy; do not weaken it. This replaces the bot PR creation step, not the validation gates. The orchestrator must actively perform this handoff; it is not an autonomous GitHub-only process.

Reel handoff: successful post-publication Reel workflow publishes reel-connector-handoff artifact and remote automation/reel branch, not a PR. Orchestrator verifies successful verification and manifest steps, artifact/log exact branch and SHA, source main commit, approved editorial input and exact manifest fields, branch diff limited to one manifest, current main absence and all existing PRs by branch and slug. Open one authenticated non-draft PR only if eligible. Existing closed PRs require explicit recovery authorization; never bypass action-required checks. Merge only after publisher approval; preview only, no social posting.

Reel artwork gate: editorial input and manifest must retain website drive_file_id separately from reel_drive_file_id, with reel_image_verified true only after explicit approval of the dedicated 1080x1920 artwork. IDs must differ. Verify both fields against approved input before opening a PR. Generator rejects non-1080x1920 artwork in all modes and saves an actual MP4 frame for visual review. Historical manifests without portrait approval are blocked; recover only with new approved artwork, not a website fallback.

Website-only intake: omit reel entirely unless separately approved. Controlled tests use [EP WEBSITE TEST] <slug> with publisher_approved:true and dry_run:true, no Reel input. Run identical intake validators in an ephemeral checkout; never push a branch, create a publication PR, or deploy test content. Test success is validation evidence only, not PR CI or live deployment evidence. Production uses [EP APPROVED PACKAGE] and dry_run must not be true.
