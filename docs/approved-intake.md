# Approved package intake
After publisher approval, create a fresh feature/<slug> branch from current main. Submit exactly one publication-intake/<slug>.json with keys slug, publisher_approved (true), article (complete JS source string), evidence (existing editorial evidence schema, exact SHA-256 of article and approved image), image_import (path, sha256, public Drive uc URL), reel (existing editorial Reel input schema, website_published false).
The workflow stages the files, imports the image, generates metadata and runs all existing validators before pushing a single finalization commit. Intake JSON is removed from the final tree; do not include secrets or private research in it, because Git history retains it. A failed run does not push staged changes. Do not open a publication PR until the intake job succeeds and its candidate SHA matches the branch head. A concurrent branch change causes a safe push failure; inspect and retry from a fresh branch if necessary. Existing importer remains available for legacy submissions. No automatic PR or merge yet. Test on a disposable feature branch before relying on production.
